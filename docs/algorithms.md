# 评分与预测算法说明

平台所有数字都出自 `backend/app/services/` 下的确定性引擎；大模型（AI 教练）只出意图和文案，
不产生任何配速 / 心率 / 成绩数字。以下均为基于公开运动科学模型的工程近似，随数据积累滚动修正，
不构成专业训练 / 医疗建议。

## 成绩预测（predictor.py）

三个模型加权融合：

1. **Riegel 外推**：`T2 = T1 × (D2/D1)^exp`，基准指数 1.06；配速慢于 6:00/km 的选手
   耐力衰减更快，指数取 1.08。每场实测比赛成绩会反推个人指数（`calibrate_riegel`），
   多场成绩校准出个人化的 exp 用于后续预测。
2. **Daniels VDOT 等效换算**（vdot.py，Daniels《Running Formula》的公式化实现，
   成绩 ↔ VDOT 互为逆运算）。
3. **临界速度模型**：`D = CS·t + D'`，用 ≥2 个距离的近期最好成绩拟合，
   得到临界速度 CS 与无氧储备 D'。**拟合优度 R²** 随拟合输出：正常跑步数据
   R² 天然 0.92-0.99（时间-距离强相关），低于 0.9 视为脏样本（如误同步的
   非跑步记录），CS 来源权重 0.55 → 0.3 降档并在质量标注中提示。

**预测区间**：三模型对同一距离的估计散布就是模型不确定性的直接度量——
输出各距离估计的加权 P25/P75 区间（`interval_sec`）；来源 <2 或散布 <1%
时缺省，区间必包住混合预测点。

**数据质量结构化**（`quality`）：成绩样本数、Riegel 校准配对数、CS 拟合
R² 与可靠性，展示层与 AI 层共用同一份事实。

**赛前快照与偏差复盘**（`race_predictions` 表）：存在未来 90 天内的目标
比赛时，预测展示入口按天留档当前预测（同场同日幂等一条）；比赛成绩录入/
修正后回填最近赛前快照，`delta_pct = (实测 − 预测) / 预测 × 100`
（正值 = 比预测慢）。比赛列表与 AI 查询均可见逐场偏差。

**生涯上限** = 当前水平 × 提升空间系数，系数由天赋分、训练年限、跑量余量、年龄决定。

## 训练状态（load_status.py / load.py）

对标佳明 / 高驰训练状态体系的工程近似：

- **训练负荷**：TRIMP（心率法）或 `时长 × RPE`（无心率数据时）。
- **7 / 28 天负荷趋势与 ACWR**（急慢性负荷比）。
- **负荷重点**：按储备心率百分比把活动归入无氧（≥88%）/ 高强度有氧（≥75%）/ 低强度有氧，
  4 周构成对照参考区间（低 55–80% / 高 15–35% / 无氧 0–12%）。
- **状态标签**：维持 / 效率良好 / 效率不佳 / 巅峰 / 恢复中 / 负荷过高 / 中断。
- **训练准备度**：睡眠、HRV、恢复时间、负荷合成 0–100。
- **单调性 / 应变**：Foster 体系。
- **有氧效率 EF**：配速 ÷ 心率趋势。
- **前瞻负荷规划**（load_project.py）：把当前训练计划代入 CTL / ATL / TSB
  逐日推演未来 12 周，给出比赛日形态与过劳警告。

## 心率区间与强度分布（zones.py）

Karvonen 储备心率法（按最大心率与静息心率换算）划区间；80/20 强度分布统计近周训练。

## 个性化身体基线（baseline.py）

对 HRV / 静息心率 / 睡眠 / 体重逐指标输出：**28 天滚动中位数**（对离档天稳健，
样本 ≥7 才给）、**MAD×1.4826 稳健波动带**（≥10 天，正态假设下等价 SD）、
最新值 **z 分数**（|z|≥2 判「明显偏低/偏高」，方向语义按指标：HRV 偏低负面、
静息心率偏高负面、睡眠偏低负面、体重双向中性）、**漂移**（近 7 天 vs 前 21 天，
±5% 判基线漂移）。样本不足一律诚实缺省。档案里的手填基线仍是用户声明口径，
两者并存展示。

**打卡客观联动**（objective_cap）：近 3 天 HRV 中位数 z≤-2 → 建议档位封顶
easy；单日 HRV z≤-2 或昨夜睡眠 <6h → 封顶 reduce；与补给状态同构「只降不升」，
主观状态已差时客观信号再差不升档。只输出档位与理由，不改课表。

## 有氧解耦与 EF（activity_detail.py / pro_insights.py / load_status.py）

- **单次解耦**（活动详情页）：把带设备逐段心率的跑步切前后两半，比较
  EF = 速度 ÷ 心率 的漂移（`(EF1−EF2)/EF1`）。护栏：40min-4h、爬升
  ≤12m/km、>50km/h 的 GPS 坏段丢弃、|解耦|>30% 视为坏样本。均心率活动
  明确返回不可算，不用均值编造漂移。
- **解耦洞察**（训练状态页）：近 8 周中位解耦，<5% 优秀 / 5-8% 合格 /
  >8% 待提升；疲劳抗性卡由后半程配速衰减与解耦合成。
- **EF 趋势**（训练状态页）：近 8 周低强度跑（储备心率 ≤75%）的
  EF = 速度(m/min) ÷ 均心率，对比之前 8 周（+2% 以上判提升）。EF 用
  m/min 口径（值域 0.5-3）——km/min 口径量级 0.001，低精度舍入会抹掉差异。

## 每日打卡建议（checkin_advice.py）

确定性规则：主观状态（睡眠 / 酸痛 / 精力 / 动力 / 疼痛部位）→ 档位
normal → reduce → easy → rest，叠加补给状态（能量亏缺只会降档不会升档）。
只输出建议档位与理由，不直接改课表；调课必须经 AI 提案 → 用户确认。

## 综合评估（evaluator.py / weakness.py）

五个维度加权：有氧能力 25% | 力量水准 15% | 意志品质 20% | 恢复能力 15% | 天赋水准 25%，
各维度 0–100 分附证据明细。VDOT → 人群百分位用 logistic 映射（中点 46、尺度 7.2，
女性等效平移 +4.5），叠加年龄 graded 修正——这部分是与用户无关的人群先验，
其余数字全部来自本人数据。短板诊断区分「可训练项」（给改进动作）与「先天特质」（给应对策略）。

## 力量评估（strength.py）

1RM 折算（Epley 类公式）、相对力量等级对照、肌群平衡诊断、跑者专项力量建议。

## 营养目标（diet.py）

营养目标随当天课型调整（质量课多碳水、休息日控碳）；能量平衡中跑步卡路里缺失时
按约 1 kcal/kg/km 估算；近 14 天输出习惯分析。
