# 功能提升清单（2026-09-30 盘点；P0-1/2/3、P1-1/2、P2-1/2 已于当日实现，P1-3/4 经确认不做）

> 依据：对 routers / services / views 全量盘点后的结论——大模块已齐，提升点集中在
> 「已同步入库但没人消费的数据」+「跑者刚需闭环缺口」+「AI 教练差异化」三条线。
> 用法：每项勾选推进；开工前先读对应「落点」提到的模块，遵守横切纪律。

## 横切纪律（每一项都适用）

- 老表加列必须登记 `db.py` 的 `_MIGRATION_DDL`；新表走 `create_all`。
- 课型判断/中文标签走 `vocab.py`，时段配速口径走 `planner.SLOT_CAP_MIN_PER_KM`。
- 一切课表变更只能「AI 提案 → 用户确认」两段式；确定性引擎只出档位与理由。
- LLM 依赖一律可退化（规则版兜底），多路 LLM 调用共用 `_LLM_GATE` 排队。
- 每项带锁定测试；改提示词/换模型后必跑 `py evals/run_evals.py`。
- 测试夹具只用守卫白名单合成数据，禁止从真实接口响应复制样例。

## P0 快赢：数据已在库里，缺的是消费端

### [x] P0-1 官方 ↔ 本地双系统交叉校验
- **现状**：`FitnessSnapshot` 每次高驰同步落一天快照（官方 VO2max、阈值配速、官方比赛预测、短/长负荷、`load_ratio`），但只有 `pro_insights` 原样展示；本地 ACWR/预测引擎完全不读它，两套体系并行无对照。
- **做法**：新 `services/crosscheck.py`：① 官方 `load_ratio` vs 本地 ACWR 背离检测（如差值超阈值持续 3 天即提示，阈值做成常量）；② 官方 VO2max 7 天滑动均值作为预测引擎的校准参考；结论挂到总览页状态卡 + `get_coach_briefing` 简报要点。
- **落点**：新 service、`routers/training_status.py` 或 `dashboard.py` 挂块、Dashboard.vue 卡片、`ai_tools.get_coach_briefing`。
- **验收**：背离检测口径锁定测试（含官方快照缺天/缺字段时如实降级）；简报含结论。

### [x] P0-2 预测演变曲线
- **现状**：`RacePrediction` 每天写赛前快照、赛后回填 delta，但没有任何端点/视图读历史序列。
- **做法**：`GET /api/stats/prediction-trend`（按目标项目过滤，返回 日期→官方预测成绩 序列 + 本地预测对照线）；Prediction 页加趋势折线图。无快照如实 empty。
- **落点**：`routers/stats.py`、`web/src/views/Prediction.vue`。
- **验收**：端点测试（有快照/无快照/跨目标项目过滤）。

### [x] P0-3 睡眠细分字段进建议引擎
- **现状**：`sleep_score` / `spo2` / `body_battery` / `resp_rate` 已随手表同步入库，但 `checkin_advice`、`baseline`、`response_curves` 只认 `hrv_rmssd` / `sleep_hours` / `resting_hr` / `weight_kg`。
- **做法**：checkin 建议与响应曲线把 `sleep_score` 作为小权重因子接入，缺值自动降级到现行口径；Health 页字段已有展示不用动。
- **落点**：`services/checkin_advice.py`、`services/response_curves.py`。
- **验收**：锁定测试两条——有 sleep_score 时建议口径变化、缺值时行为与现状完全一致。

## P1 闭环：把半成品接成完整回路

### [x] P1-1 伤病结构化追踪（最明显的刚需空白）
- **现状**：伤病史只有 `coach_notes` 自由文本（remember_user_note 的 injury 类别）+ 若干文案提醒，无法做时间线关联。
- **做法**：`injury_logs` 新表（create_all）：部位 / 侧别 / 等级(1-3) / 起止日期 / 备注；CRUD 端点 + Health 页录入卡；关联分析：伤病起始日与前 7 天 ACWR 高位段的重合统计；恢复期 return-to-run 渐进建议（checkin 建议引擎模式：只出档位+理由，不直接改课表）。
- **落点**：新表、`routers/health.py`、新 service（建议放 `services/injury.py`）、Health.vue、`get_coach_briefing` 带活跃伤病、`get_daily_checkin` 返回活跃伤病信号。
- **验收**：表/端点/关联分析/建议档位测试；教练记忆自由文本功能保持不变。

### [x] P1-2 比赛中心聚合页
- **现状**：赛时计划（Prediction tab 底部卡）、负荷预测（TrainingStatus）、倒计时、天气修正分散三处。
- **做法**：聚合「比赛中心」（新视图或 Prediction 页扩展）：倒计时、taper 减量对照（赛周负荷 vs 峰值周，规则如降至 30–60%，数据复用 `load_forecast`）、race_strategy 配速卡 + 天气修正、装备清单（gear 中勾选比赛鞋）。
- **落点**：`races.py` 或新 router、新/改视图、`services/race_strategy.py`、`services/load_project.py`。
- **验收**：taper 对照口径锁定测试；无比赛目标/无计划时如实 empty。

### [ ] P1-3 补给计划个性化
- **现状**：race_strategy 的补给是静态规则；`diet_logs` 已记录长课日摄入，`DailyCheckin` 有次日身体反应。
- **做法**：长课补给实战回看——读长课日的 diet 记录 + 次日打卡，把验证过的补给组合（碳水/补剂/时机）写进赛时计划的补给段，标注「实战验证 / 赛前首试」；无记录退回静态规则。
- **落点**：`services/race_strategy.py`、`services/diet.py` 取数函数。
- **验收**：有/无 diet 数据两条路径测试；肠胃反应字段缺失时不误导。

### [ ] P1-4 装备决策支持
- **现状**：gear 已有里程累计 / 退役警告 / 活动↔跑鞋关联。
- **做法**：① 比赛鞋建议（按目标项目静态规则 + 各鞋实际里程与磨合度）；② 按鞋分组的身体反应对比（复用 response_curves 思路，样本不足如实 insufficient）。
- **落点**：`routers/gear.py`、RecordsCenter 装备 tab、`services/response_curves.py` 泛化。
- **验收**：建议规则测试；对比样本 <3 标 insufficient（对齐现有口径）。

## P2 AI 教练层：延续差异化路线

### [x] P2-1 主动式教练晨报
- **现状**：AI 教练完全被动（问才答）；dashboard 聚合、weekly_recap、plan_drift、教练人设的数据管道全通。
- **做法**：每天首次打开总览页后台生成「今晨要点」：今日课 + 恢复状态 + 天气 + 执行率 + 活跃伤病，两三句，按人设口吻（走 `_LLM_GATE` 排队）；落库且支持就地追问。模型不可用退化为规则版，不是硬依赖。
- **落点**：新 service（如 `services/morning_brief.py`）、`routers/dashboard.py`、Dashboard.vue 卡片、`coach_persona`。
- **约束**：人设遵循度与篇幅成反比，提示词保持紧凑；人设只做风格层，数字纪律/提案铁律独立段落。
- **验收**：生成/退化/每日只生成一次三个场景测试；改提示词后跑 evals。

### [x] P2-2 预测校准报告
- **现状**：`get_race_history` 已有「预测 vs 实际」概念，RacePrediction 赛后回填 delta，但没有显式视图。
- **做法**：AnalysisCenter 加校准卡：历次比赛赛前预测 vs 实际成绩的偏差表（按项目分组）；race_strategy 配速建议附「校准状态」标注（有历史偏差时显示 ±X% 置信，无则标注未校准）。
- **落点**：`races.py`、`services/race_strategy.py`、AnalysisCenter / CoachScorecard 同层卡片。
- **依赖**：P0-2 的取数面。
